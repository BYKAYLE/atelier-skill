# 런타임 검증 및 브라우저 시각 검증 상세

## S-Phase 3.3 / F-Phase 3.3: 빌드 + 런타임 검증 (v5.0)

Phase 3(정적 분석 QC)이 "코드를 읽었을 때 문제가 없는가"를 검증했다면, Phase 3.3은 "실제로 빌드하고 실행했을 때 동작하는가"를 검증한다.

런타임 검증 에이전트(Sonnet)가 실행한다:

### 1. 빌드 검증 — 프로젝트가 에러 없이 빌드되는가
- 프론트엔드: `npm run build` / `pnpm build` 등 → exit code 0 확인
- 백엔드: Python import 체크, TypeScript `tsc --noEmit` 등
- Docker: `docker compose build` 성공 여부 (Docker 프로젝트일 때)

### 2. DB 마이그레이션 검증 — DB가 있는 프로젝트에서 스키마가 올바른가
- 마이그레이션 스크립트 실행 가능 여부 (`alembic upgrade head`, `prisma migrate deploy` 등)
- 모델 정의와 마이그레이션 파일의 일관성

### 3. 런타임 Smoke Test — 서버를 실제로 기동하고 핵심 동작을 검증
- 서버 기동 → 에러 없이 listening 상태 확인
- 헬스체크 엔드포인트 호출 (GET /, /health, /api/health 등)
- 핵심 API 엔드포인트별 정상 요청 → 기대 응답 코드 확인
- 인증 흐름: 회원가입 → 로그인 → 토큰 발급 → 인증 필요 API 호출
- 프론트엔드 페이지 로드: 각 라우트별 HTML 응답 확인 (200 OK)

### 4. API 계약 테스트 — API 스키마와 실제 응답이 일치하는가
- 응답 JSON 필드명이 프론트엔드가 기대하는 형식과 일치하는지 (camelCase/snake_case)
- 필수 필드 누락 여부
- 에러 응답 형식 일관성

### 판정
- **PASS** → 빌드 성공 + 서버 기동 + 핵심 API 정상 → Phase 3.5 진행
- **FAIL** → 수정 에이전트(빌더)에게 전달하여 수정 후 재검증 (최대 3회)
- **[필수 게이트] 런타임 검증 완료 시 issues.md 갱신** — 발견된 런타임 이슈 기록

### 피처 빌더 스코프 조정 (F-Phase 3.3)
- 빌드 검증: 전체 프로젝트 빌드 (변경이 빌드를 깨뜨리지 않는지)
- DB 마이그레이션: 새 마이그레이션이 있는 경우에만
- 런타임 Smoke Test: 신규 API + 기존 핵심 API 모두 테스트 (회귀 확인)
- API 계약 테스트: 변경된 엔드포인트 중심으로 프론트엔드 연동 확인

## S-Phase 3.7 / F-Phase 3.7: 브라우저 시각 검증 (v5.0, 선택)

Phase 3.5까지가 "코드 레벨에서 안전한가"를 검증했다면, Phase 3.7은 "사용자가 실제로 보는 화면이 의도대로인가"를 검증한다.

이 Phase는 **선택적**이다. 아래 조건 중 하나 이상 해당할 때 실행한다:
- 프로젝트에 프론트엔드(웹 UI)가 포함되어 있다
- ui-guide.md가 존재한다
- 이전 QC에서 UI 관련 이슈가 발견되었다

브라우저 검증 에이전트(Sonnet)가 실행한다:

### 1. 서비스 기동
Docker Compose 또는 개발 서버를 실행한다.

### 2. 주요 화면 스크린샷
각 핵심 페이지/라우트의 스크린샷을 캡처한다:
- 데스크톱(1280px), 모바일(375px) 각각
- 로그인 전/후 화면 구분

### 3. 시각 검증 — 스크린샷을 ui-guide.md와 대조한다
- 색상 팔레트 준수 여부
- 레이아웃 깨짐 여부
- 빈 상태/에러 상태 화면 확인
- 모바일 가로 스크롤 발생 여부

### 4. 인터랙션 검증 — 주요 사용자 흐름을 수동으로 테스트한다
- 폼 제출 → 결과 확인
- 네비게이션 이동
- 로딩/에러 상태 전환

### 판정
- **PASS** → 시각 이슈 없음 → Phase 4 진행
- **ISSUES** → issues.md에 기록 (심각도에 따라 즉시 수정 또는 DEFERRED)

### 피처 빌더 스코프 조정 (F-Phase 3.7)
- 새로 추가된 페이지/컴포넌트의 스크린샷
- 기존 페이지 중 영향받는 화면의 회귀 검증
- 모바일/데스크톱 반응형 확인
