# UI 디자인 프로세스 (S-Phase 1.7 상세)

기획 승인 후, **빌드 전에 UI 방향을 결정한다.** 디자인 에이전트 담당.

3단계 깔때기 구조: Stage가 올라갈수록 시안 수는 줄고 완성도는 높아진다.
- **Stage 1** (컨셉 탐색): 8~10개 경량 시안 → 2~3개 방향 선정
- **Stage 2** (방향 정교화): 4~6개 풀 HTML 시안 → 최종 1개 확정
- **Stage 3** (델타 퓨전): 3~5개 베리에이션 미세 조정 → 최종 확정

## Step 0. 디자인 인텔리전스 조회

`~/.claude/skills/ui-ux-pro-max/SKILL.md` 존재 시 실행 (없으면 Step 1로 건너뜀):
1. planning.md에서 제품 유형/산업 키워드 추출
2. ui-ux-pro-max 4단계 워크플로우 실행 (요구사항 분석 → 디자인 시스템 생성 → 보조 리서치 → 스택 구현 규칙)
3. 결과를 SOT/design-intelligence.md에 저장 (스타일, 색상 팔레트, 폰트, 접근성, 반응형 규칙)
4. Stage 1~3에서 시안의 기초로 사용

## 사전 준비

**Step 1. UI 선호도 수집** — 시안 전에 사용자 방향을 파악한다:
- 원하는 분위기/톤 (전문적/캐주얼/미니멀/역동적/따뜻한 등)
- 선호하는 색감 (다크/라이트/특정 색상 등)
- 참고하고 싶은 서비스나 웹사이트
- 싫어하는 스타일 (피해야 할 방향)
- → SOT/ui-preferences.md에 저장

**Step 2. UI 레퍼런스 수집** — 선호도 + 시장 리서치를 결합:
- 참고 서비스의 UI 분석
- 경쟁 제품(market-research.md) UI 트렌드
- 타겟 사용자에게 적합한 UI 톤 도출
- → SOT/ui-references.md에 저장

## Stage 1: 컨셉 탐색 ✋

**Step 3.** 선호도 + 레퍼런스 + 디자인 인텔리전스 기반으로 **8~10개 경량 시안** 생성
- 스타일 카드 수준 (핵심 화면 1개, 정적 HTML, 인터랙션 없음)
- 같은 조건을 서로 다르게 해석 (레이아웃/색상/타이포/아이콘/여백/강조 변주)
- 각 시안에 이름 + 1줄 컨셉 설명

**Step 4.** 비교표와 함께 제시 → 사용자가 2~3개 방향 선정 + 좋았던 요소 피드백 → SOT/ui-stage1-selection.md

## Stage 2: 방향 정교화 ✋

**Step 5.** 선택된 방향 기반 **4~6개 풀 HTML 시안** 생성
- 핵심 화면 1~2개를 실동작 수준 구현 (인터랙션 포함)
- 방향별 2~3개 변주 + Stage 1 피드백 적극 반영

**Step 6.** 상세 비교표 제시 → **최종 1개 확정** (부분 조합 가능) → SOT/ui-stage2-selection.md

## Stage 3: 델타 퓨전 ✋

**Step 7.** 확정 시안 기반 **3~5개 베리에이션** (1~2개 요소만 미세 변주)
- 기준(Base) 시안과 함께 제시 → 사용자 선택 (기준 유지 / 베리에이션 선택 / 추가 조정, 최대 3회 반복)
- 확정 결과 → SOT/ui-delta-fusion.md

## Step 8. UI 가이드 확정

최종 결과를 SOT/ui-guide.md에 정리: 색상 팔레트, 폰트 체계, 아이콘 스타일, 레이아웃 패턴, 컴포넌트 스타일, 분위기 키워드.

**자체검증**: UI 가이드가 델타 퓨전 결과를 정확히 반영하는가? 사용자가 좋아한 요소가 빠지지 않았는가?
