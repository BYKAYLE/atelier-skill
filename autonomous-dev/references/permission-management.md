# 권한 관리 (v2.0)

"무중단" 원칙을 실현하기 위한 권한 관리 체계. 빌드 중 권한 팝업으로 작업이 끊기는 것을 방지한다.

## 사전 승인 프로세스

**Phase 2(빌드) 진입 직전**에 리더가 한 번에 처리한다:

1. **필요 권한 파악** — tasks.md의 작업 목록을 분석하여 빌더가 사용할 도구/명령어를 도출
2. **권한 목록 안내** — 사용자에게 한 번에 제시:
   ```
   이번 빌드에서 다음 작업이 필요합니다:
   - 파일 생성/수정: src/ 하위 파일들
   - 패키지 설치: npm install / pnpm install
   - 빌드 실행: npm run build
   - 코드 실행: node, python3 (테스트/검증용)
   - 브라우저 열기: open (결과물 확인용)

   진행할까요?
   ```
3. **일괄 승인** — 사용자가 승인하면 Phase 2~3.7까지 무중단 진행

## 에이전트별 권한 경계

| 에이전트 | 허용 | 금지 |
|---------|------|------|
| **빌더** | Read, Write, Edit, Glob, Grep, Bash(빌드/테스트/패키지 설치/코드 실행) | git push, 외부 서비스 호출, 환경변수 파일 수정, 시스템 설정 변경 |
| **QC** | Read, Glob, Grep, Bash(코드 실행/테스트/브라우저 열기), Write(보고서 파일만: qc-result.md, 차단 보고서) | Edit, src/ 코드 수정 (QC는 코드를 수정하지 않는다) |
| **런타임 검증** (v5.0) | Read, Glob, Grep, Bash(빌드/서버 기동/API 호출/Docker/curl), Write(runtime-qc-result.md만) | Edit, src/ 코드 수정 |
| **Final QC** | Read, Glob, Grep, Bash(정적 분석/실행 테스트), Write(감사 보고서만) | Edit, src/ 코드 수정 (감사는 보고만 한다) |
| **브라우저 검증** (v5.0) | Read, Glob, Grep, Bash(서버 기동/브라우저 열기/스크린샷), Write(visual-qc-result.md만) | Edit, src/ 코드 수정 |
| **문서** | Read, Write, Edit (SOT 파일만) | Bash, src/ 코드 수정 |

## 보안 경계 (절대 규칙)

어떤 에이전트도 아래 행위를 하지 않는다. 리더도 예외 없음:

```
절대 금지:
- git push / git push --force (사용자가 직접 할 때까지 대기)
- .env 파일 내용 출력/로그 기록
- rm -rf, 대규모 파일 삭제 (명시적 사용자 요청 없이)
- 외부 API에 인증 정보 전송
- 사용자 홈 디렉토리 밖 파일 수정
- npm publish, docker push 등 배포 행위

조건부 허용 (리더 판단 후):
- 파일 삭제 (리팩토링 시, 삭제 목록을 report.md에 기록)
- 새 패키지 설치 (기획서에 명시되지 않은 패키지)
- 포트 바인딩 (개발 서버 실행 시)
```

## 권한 위반 시

빌더가 금지된 작업을 시도하여 권한 팝업이 발생하면:
1. 리더가 해당 빌더를 중단
2. 작업 지시에서 금지 행위를 제거한 뒤 새 빌더로 재시도
3. 위반 내용을 decisions.md에 기록 ("빌더가 X를 시도 → 차단 → Y로 대체")
