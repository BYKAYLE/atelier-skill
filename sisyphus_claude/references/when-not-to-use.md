# When Not To Use `sisyphus_claude`

다음 경우에는 `sisyphus_claude`보다 다른 흐름이 더 적합할 수 있다.

## 1. 설명이 더 중요한 작업

- 사용자가 중간 reasoning과 탐색 결과를 계속 같이 보고 싶을 때
- 이 경우 `sisyphus-workflow`가 더 적합하다.

## 2. 아주 작은 단발성 작업

- 한 줄 설명, 사소한 질의응답, 단순 정보 요청
- 굳이 release-loop 성향이 필요하지 않다.

## 3. 강한 상호작용이 필요한 작업

- 사용자가 단계마다 결정을 내려야 하는 협업형 작업
- blocker-only questioning보다 더 잦은 대화가 필요한 경우

## 4. 실서비스 인증/배포 중심 작업

- 계정 인증, 실배포, 결제/보안 posture 변경이 중심인 작업
- 이 경우에도 사용할 수는 있지만, 질문/승인 비중이 커져 장점이 줄어든다.
