# 디자인 원칙 백과사전

## 1. 게슈탈트 원칙 (Gestalt Principles)

인간의 시각 인지 체계가 요소들을 어떻게 그룹핑하고 해석하는지에 대한 원칙.

### 1.1 근접성 (Proximity)
가까이 있는 요소들은 하나의 그룹으로 인식된다.

**적용 규칙:**
- 관련 요소 간 간격: 8~16px
- 비관련 요소 간 간격: 24~48px
- 그룹 간 간격은 그룹 내 간격의 최소 2배
- 폼 필드와 레이블 간격: 4~8px
- 폼 필드 간 간격: 16~24px
- 섹션 간 간격: 48~96px

```css
/* 근접성 적용 예시 */
.form-group {
  margin-bottom: 24px; /* 그룹 간 간격 */
}
.form-group label {
  margin-bottom: 4px; /* 레이블-입력 간 간격 */
  display: block;
}
.form-group .helper-text {
  margin-top: 4px; /* 입력-도움말 간 간격 */
}
.section {
  margin-bottom: 64px; /* 섹션 간 간격 */
}
```

### 1.2 유사성 (Similarity)
시각적으로 비슷한 요소들은 같은 그룹으로 인식된다.

**적용 규칙:**
- 같은 기능의 요소는 같은 색상, 크기, 모양 사용
- 카테고리별로 아이콘 스타일 통일 (Outlined면 전부 Outlined)
- 상태 표시 일관성: 성공=녹색, 경고=주황, 오류=빨강 전체 앱에서 통일
- 클릭 가능한 요소는 동일한 시각적 처리 (밑줄, 색상, 커서)

```css
/* 유사성 적용 — 카드 그룹 */
.card {
  border-radius: 12px;
  padding: 24px;
  background: #FFFFFF;
  border: 1px solid #E5E7EB;
}
.card--featured {
  border-color: #3B82F6; /* 같은 형태, 강조만 다름 */
  box-shadow: 0 0 0 1px #3B82F6;
}
```

### 1.3 폐합성 (Closure)
불완전한 형태도 완전한 형태로 인식하려는 경향.

**적용 규칙:**
- 카드에 명시적 테두리 없이도 배경색/그림자로 영역 구분 가능
- 탭 인터페이스에서 활성 탭과 콘텐츠 영역을 색상으로 연결
- 아이콘 디자인 시 일부를 생략해도 인식 가능 (간결한 아이콘)
- 프로그레스 바에서 빈 부분도 전체 경로로 인식

### 1.4 연속성 (Continuity)
시선은 직선이나 곡선을 따라 자연스럽게 이동한다.

**적용 규칙:**
- 스텝 인디케이터는 직선/곡선으로 연결
- 타임라인 UI는 세로/가로 선으로 연결
- 네비게이션은 시선의 자연스러운 흐름을 따름
- 카드 목록은 일관된 정렬선을 유지

### 1.5 공동 운명 (Common Fate)
같은 방향으로 움직이는 요소들은 하나의 그룹으로 인식된다.

**적용 규칙:**
- 그룹 호버 시 모든 하위 요소가 동시에 반응
- 드래그 앤 드롭 시 관련 요소가 함께 이동
- 스크롤 시 고정 헤더와 스크롤 콘텐츠 구분

```css
/* 공동 운명 — 카드 호버 */
.card:hover {
  transform: translateY(-2px);
  box-shadow: 0 8px 24px rgba(0, 0, 0, 0.12);
}
.card:hover .card__title {
  color: #3B82F6; /* 카드 전체와 함께 반응 */
}
```

### 1.6 그림과 배경 (Figure-Ground)
전경(주요 요소)과 배경을 구분하는 원칙.

**적용 규칙:**
- 모달은 배경을 어둡게 처리하여 전경 강조
- 포커스된 요소는 주변보다 높은 대비
- 플로팅 액션 버튼은 그림자로 배경과 분리
- 드롭다운 메뉴는 그림자/테두리로 배경과 분리

```css
/* 그림과 배경 — 모달 오버레이 */
.modal-overlay {
  background: rgba(0, 0, 0, 0.5);
  backdrop-filter: blur(4px);
}
.modal-content {
  background: #FFFFFF;
  border-radius: 16px;
  box-shadow: 0 24px 48px rgba(0, 0, 0, 0.2);
}
```

## 2. 시각적 계층 구조 (Visual Hierarchy)

사용자의 시선을 의도된 순서로 유도하는 체계.

### 2.1 크기 계층

| 레벨 | 용도 | 크기 범위 |
|------|------|----------|
| Level 1 | 페이지 제목, Hero 텍스트 | 36~72px |
| Level 2 | 섹션 제목 | 24~36px |
| Level 3 | 카드 제목, 서브섹션 | 18~24px |
| Level 4 | 본문 텍스트 | 14~16px |
| Level 5 | 보조 텍스트, 캡션 | 12~14px |
| Level 6 | 메타 정보, 타임스탬프 | 10~12px |

### 2.2 굵기 계층

| 용도 | Font Weight |
|------|------------|
| Hero / 강조 제목 | 800~900 (ExtraBold~Black) |
| 섹션 제목 | 700 (Bold) |
| 카드 제목 / 라벨 | 600 (SemiBold) |
| 본문 강조 | 500 (Medium) |
| 본문 일반 | 400 (Regular) |
| 보조 텍스트 | 300~400 (Light~Regular) |

### 2.3 색상 계층

```css
:root {
  --text-primary: #111827;     /* 제목, 핵심 텍스트 */
  --text-secondary: #4B5563;   /* 본문 */
  --text-tertiary: #6B7280;    /* 보조 설명 */
  --text-quaternary: #9CA3AF;  /* 비활성, 플레이스홀더 */
  --text-disabled: #D1D5DB;    /* 비활성 상태 */
}
```

### 2.4 간격 계층

요소의 중요도가 높을수록 주변 여백이 넓다:
- Hero 섹션: 상하 80~120px
- 주요 섹션: 상하 48~64px
- 서브 섹션: 상하 24~32px
- 일반 요소: 상하 8~16px

## 3. CARP 원칙

### 3.1 대비 (Contrast)
서로 다른 요소는 확실히 다르게 만든다.

**규칙:**
- 제목과 본문 크기 차이 최소 1.5배
- 활성/비활성 상태는 투명도 뿐 아니라 색상도 변경
- CTA 버튼은 주변 요소와 최소 3:1 대비
- 텍스트-배경 대비비: 일반 4.5:1, 대형(18px+) 3:1

### 3.2 정렬 (Alignment)
모든 요소는 보이지 않는 선에 맞춰 정렬한다.

**규칙:**
- 좌측 정렬 기본 (LTR 언어)
- 중앙 정렬은 제목, Hero 텍스트, CTA에만 사용
- 우측 정렬은 숫자, 가격, 날짜에 사용
- 혼합 정렬 금지 — 한 섹션 내에서 정렬 방식을 통일

```css
/* 정렬 기준선 */
.container {
  max-width: 1200px;
  margin: 0 auto;
  padding: 0 24px;
}
.content-left { text-align: left; }
.content-center { text-align: center; }
.price { text-align: right; font-variant-numeric: tabular-nums; }
```

### 3.3 반복 (Repetition)
동일한 시각적 처리를 반복하여 일관성과 통일감을 만든다.

**규칙:**
- 같은 레벨의 제목은 같은 스타일
- 아이콘 세트는 하나의 스타일 (Outlined/Filled/Rounded 중 하나)
- 버튼 라디우스는 전체 앱에서 통일
- 간격 스케일을 정의하고 임의 값 사용 금지

### 3.4 근접 (Proximity)
— 게슈탈트 근접성과 동일. 관련 항목은 가깝게, 비관련은 멀게.

## 4. 피츠의 법칙 (Fitts's Law)

타겟에 도달하는 시간은 타겟까지의 거리와 타겟의 크기에 비례한다.

**T = a + b × log₂(2D/W)**
- T: 도달 시간, D: 거리, W: 타겟 크기

**적용 규칙:**

| 요소 | 최소 크기 | 권장 크기 |
|------|----------|----------|
| 데스크톱 버튼 | 32×32px | 40×40px |
| 모바일 터치 타겟 | 44×44px (iOS) | 48×48dp (Android) |
| 네비게이션 항목 | 높이 40px | 높이 48px |
| 툴바 아이콘 | 24×24px + 8px 패딩 | 24×24px + 12px 패딩 |

**핵심 규칙:**
- 자주 사용하는 버튼일수록 크게 만든다
- CTA 버튼은 주변 버튼보다 1.5~2배 크게
- 모바일에서 하단 영역이 엄지로 닿기 쉬움 (Thumb Zone)
- 삭제 등 위험한 액션은 작게 + 멀리 배치
- 화면 가장자리에 있는 요소는 무한 크기 효과 (메뉴바, 스크롤바)

```css
/* 피츠의 법칙 적용 */
.btn-primary {
  min-height: 44px;
  min-width: 120px;
  padding: 12px 24px;
}
.btn-icon {
  width: 44px;
  height: 44px;
  display: flex;
  align-items: center;
  justify-content: center;
}
/* 모바일 하단 고정 CTA */
.mobile-cta {
  position: fixed;
  bottom: 0;
  left: 0;
  right: 0;
  padding: 16px;
  padding-bottom: calc(16px + env(safe-area-inset-bottom));
}
```

## 5. 히크의 법칙 (Hick's Law)

선택지가 많을수록 결정에 걸리는 시간이 길어진다.

**T = b × log₂(n + 1)**
- T: 결정 시간, n: 선택지 수

**적용 규칙:**
- 네비게이션 메뉴 항목: 최대 7개 (모바일은 5개)
- 드롭다운 선택지: 7개 초과 시 검색 기능 추가
- 설정 페이지: 카테고리로 그룹핑하여 한 번에 5~7개만 표시
- 대시보드 위젯: 한 화면에 최대 6~8개
- 가격 플랜: 3~4개 (추천 플랜 강조)
- CTA 버튼: 한 화면에 주요 CTA 1개만

**실천 방법:**
1. 카테고리화 — 15개 항목을 3개 그룹 × 5개로 분류
2. 점진적 공개 — 자주 쓰는 5개만 표시, "더 보기"로 나머지 숨김
3. 추천/기본값 — 가장 흔한 선택을 기본값으로 설정
4. 검색 — 10개 이상의 선택지에는 반드시 검색 기능

## 6. 야콥의 법칙 (Jakob's Law)

사용자는 대부분의 시간을 "다른 사이트"에서 보낸다. 따라서 다른 사이트와 동일한 방식으로 동작하기를 기대한다.

**적용 규칙:**
- 로고는 좌상단, 클릭 시 홈으로 이동
- 검색은 상단 중앙 또는 우상단
- 장바구니 아이콘은 우상단
- 모바일 네비게이션은 하단 탭바 또는 햄버거 메뉴
- 뒤로 가기는 좌상단 화살표
- 스와이프 제스처: 좌→우 = 뒤로, 아래로 당기기 = 새로고침
- 폼 제출 버튼은 폼 하단 우측
- 취소 버튼은 확인 버튼의 좌측

## 7. 밀러의 법칙 (Miller's Law)

단기 기억의 용량은 7±2개 항목이다.

**적용 규칙:**
- 한 번에 표시하는 정보 청크: 5~9개
- 전화번호 표시: 010-1234-5678 (3-4-4 청킹)
- 카드번호 표시: 1234 5678 9012 3456 (4자리씩 청킹)
- 스텝 인디케이터: 최대 7단계
- 브레드크럼: 최대 5단계
- 태그/필터: 한 번에 보이는 것 5~7개, 나머지 "+N more"

```html
<!-- 청킹 적용 — 전화번호 입력 -->
<div class="phone-input">
  <input type="tel" maxlength="3" placeholder="010">
  <span class="separator">-</span>
  <input type="tel" maxlength="4" placeholder="1234">
  <span class="separator">-</span>
  <input type="tel" maxlength="4" placeholder="5678">
</div>
```

## 8. F패턴과 Z패턴 읽기

### 8.1 F패턴
텍스트 중심 페이지에서 사용자의 시선 패턴.

**적용 대상:** 블로그, 뉴스, 문서, 검색 결과
**규칙:**
- 첫 두 줄이 가장 많이 읽힘 → 핵심 정보를 상단에 배치
- 좌측이 우측보다 더 많이 읽힘 → 중요 요소는 좌측 배치
- 스캔을 돕기 위해: 소제목, 불릿, 볼드 활용
- 문단 첫 단어에 핵심 키워드 배치

### 8.2 Z패턴
시각적 요소 중심 페이지에서 사용자의 시선 패턴.

**적용 대상:** 랜딩 페이지, 마케팅 페이지, 대시보드
**규칙:**
- 좌상단: 로고/브랜드
- 우상단: CTA 또는 네비게이션
- 좌하단: 부가 정보
- 우하단: 최종 CTA
- 대각선 경로에 핵심 콘텐츠 배치

```
┌──────────────────────────────┐
│ 로고          네비게이션  CTA │  ← 1번 시선
│        \                     │
│         \    핵심 콘텐츠     │  ← 2번 시선 (대각선)
│          \                   │
│ 부가정보          최종 CTA   │  ← 3번 시선
└──────────────────────────────┘
```

## 9. 여백의 미학 (Whitespace)

### 9.1 매크로 여백 (Macro Whitespace)
섹션, 컴포넌트 사이의 큰 여백.

| 용도 | 권장 여백 |
|------|----------|
| 섹션 간 | 64~120px |
| 헤더-콘텐츠 | 32~48px |
| 콘텐츠-푸터 | 64~96px |
| 사이드바-콘텐츠 | 24~32px |

### 9.2 마이크로 여백 (Micro Whitespace)
요소 내부, 텍스트 사이의 작은 여백.

| 용도 | 권장 여백 |
|------|----------|
| 아이콘-텍스트 | 8px |
| 레이블-입력 | 4~8px |
| 문단 간 | 16px |
| 리스트 항목 간 | 8~12px |
| 버튼 내부 패딩 | 12px 24px |

### 9.3 여백의 효과
- 넓은 여백 = 고급스러움, 여유, 프리미엄 (Apple, Aesop)
- 좁은 여백 = 정보 밀도, 효율, 전문성 (Bloomberg, 트레이딩 앱)
- 균일한 여백 = 질서, 신뢰 (정부 사이트, 은행)

## 10. 인지 부하 (Cognitive Load) 관리

### 10.1 내재적 부하 (Intrinsic Load)
과제 자체의 복잡성. 줄일 수 없지만 관리할 수 있다.

**관리 방법:**
- 복잡한 폼은 스텝으로 분할 (Wizard/Stepper)
- 한 화면에 하나의 과제만
- 관련 정보를 그룹핑

### 10.2 외재적 부하 (Extraneous Load)
나쁜 디자인이 추가하는 불필요한 부하.

**제거 방법:**
- 장식적 요소 최소화
- 일관된 인터페이스 (같은 기능 = 같은 모양)
- 명확한 레이블과 지시문
- 불필요한 선택지 제거
- 자동 완성, 기본값 제공

### 10.3 생성적 부하 (Germane Load)
학습과 이해에 사용되는 유익한 부하.

**강화 방법:**
- 의미 있는 그룹핑과 카테고리
- 시각적 비유 (아이콘, 일러스트)
- 점진적 온보딩
- 컨텍스트 도움말

```css
/* 인지 부하 관리 — 폼 스텝 */
.stepper {
  display: flex;
  justify-content: center;
  gap: 8px;
  margin-bottom: 32px;
}
.stepper__step {
  width: 32px;
  height: 32px;
  border-radius: 50%;
  display: flex;
  align-items: center;
  justify-content: center;
  font-size: 14px;
  font-weight: 600;
}
.stepper__step--active {
  background: #3B82F6;
  color: #FFFFFF;
}
.stepper__step--completed {
  background: #10B981;
  color: #FFFFFF;
```

## 11. 어포던스와 시그니파이어

### 11.1 어포던스 (Affordance)
객체가 제공하는 행동 가능성.

| 어포던스 | 시각적 표현 |
|---------|-----------|
| 클릭 가능 | cursor: pointer, 밑줄, 색상 변경 |
| 드래그 가능 | grab cursor, 드래그 핸들 (⋮⋮) |
| 입력 가능 | 테두리가 있는 빈 영역, 플레이스홀더 |
| 스크롤 가능 | 스크롤바, 콘텐츠 잘림 (fade-out) |
| 크기 조절 가능 | 모서리 리사이즈 핸들 |
| 토글 가능 | 스위치 UI, 체크박스 |

### 11.2 시그니파이어 (Signifier)
어포던스를 사용자에게 알려주는 시각적 단서.

```css
/* 시그니파이어 — 클릭 가능 */
.clickable {
  cursor: pointer;
  color: #3B82F6;
  transition: color 0.15s;
}
.clickable:hover {
  color: #2563EB;
  text-decoration: underline;
}

/* 시그니파이어 — 드래그 가능 */
.draggable {
  cursor: grab;
}
.draggable:active {
  cursor: grabbing;
}
.drag-handle::before {
  content: "⋮⋮";
  color: #9CA3AF;
  font-size: 12px;
}

/* 시그니파이어 — 스크롤 가능 */
.scrollable {
  overflow: auto;
  position: relative;
}
.scrollable::after {
  content: "";
  position: absolute;
  bottom: 0;
  left: 0;
  right: 0;
  height: 40px;
  background: linear-gradient(transparent, var(--bg-color));
  pointer-events: none;
}
```

## 12. 점진적 공개 (Progressive Disclosure)

필요할 때 필요한 만큼만 보여준다.

**적용 패턴:**

| 패턴 | 사용 시점 |
|------|----------|
| "더 보기" 버튼 | 긴 텍스트, 목록 |
| 아코디언 | FAQ, 설정, 상세 정보 |
| 탭 | 카테고리별 콘텐츠 |
| 툴팁 | 보조 설명 |
| 모달/시트 | 부가 작업 |
| 멀티스텝 폼 | 복잡한 입력 과정 |
| 컨텍스트 메뉴 | 자주 안 쓰는 액션 |
| 고급 설정 | 파워 유저 옵션 |

**규칙:**
- 첫 화면에는 80%의 사용자가 필요한 것만
- 나머지 20%는 한 번의 인터랙션으로 접근 가능하게
- 숨긴 것의 존재를 암시해야 한다 ("고급 옵션", "+3 more")
- 숨겨진 콘텐츠에 접근하는 경로는 명확해야 한다

## 13. 멘탈 모델 (Mental Model)

사용자가 시스템이 어떻게 동작할 것인지에 대해 가지는 기대.

**일치시키는 방법:**
- 실제 세계의 비유 사용 (장바구니, 폴더, 휴지통)
- 관습적 위치에 요소 배치 (야콥의 법칙)
- 즉각적 피드백 (클릭 → 즉시 반응)
- 되돌리기 가능 (Ctrl+Z, undo)
- 에러 예방 (확인 대화상자, 입력 유효성)

**멘탈 모델 위반 시:**
- 사용자가 혼란을 느끼고 불신
- "이 앱은 이상하다"는 인상
- 학습 비용 증가, 이탈률 증가

## 14. 일관성의 4가지 유형

### 14.1 시각적 일관성
같은 유형의 요소는 같은 모양.
- 모든 버튼의 라디우스 통일
- 아이콘 세트 하나만 사용
- 색상 팔레트 준수

### 14.2 기능적 일관성
같은 모양의 요소는 같은 동작.
- 파란 텍스트 = 항상 링크
- 빨간 버튼 = 항상 파괴적 액션
- 우상단 X = 항상 닫기

### 14.3 내부 일관성
앱 내 모든 페이지에서 동일한 규칙.
- 사이드바 위치 고정
- 헤더 구조 통일
- 폼 레이아웃 통일

### 14.4 외부 일관성
다른 앱/플랫폼과의 일관성.
- iOS 앱은 iOS 가이드라인 준수
- 이커머스는 이커머스 관습 준수
- 검색 아이콘 = 돋보기

## 15. 추가 원칙

### 15.1 도허티 임계값 (Doherty Threshold)
시스템 응답이 400ms 이내면 사용자의 집중이 유지된다.

**적용:**
- 버튼 클릭 피드백: 100ms 이내
- 페이지 전환: 300ms 이내
- 데이터 로딩: 1초 이내 (초과 시 스피너 표시)
- 3초 이상 걸리면 프로그레스 바 + 남은 시간 표시

### 15.2 심미적 사용성 효과 (Aesthetic-Usability Effect)
아름다운 디자인은 사소한 사용성 문제를 관대하게 만든다.

**적용:**
- 시각적 품질에 투자하면 UX 부채를 부분적으로 상쇄
- 하지만 근본적 사용성 문제는 해결할 수 없다
- 미적 요소와 기능성의 균형이 중요

### 15.3 폰 레스토프 효과 (Von Restorff Effect)
시각적으로 다른 항목이 가장 잘 기억된다.

**적용:**
- CTA 버튼은 주변과 확실히 다른 색상
- 중요 알림은 배경색 + 아이콘으로 강조
- 가격표에서 추천 플랜을 시각적으로 두드러지게

```css
/* 폰 레스토프 효과 — 추천 플랜 */
.pricing-card {
  background: #FFFFFF;
  border: 1px solid #E5E7EB;
  border-radius: 16px;
  padding: 32px;
}
.pricing-card--recommended {
  background: #EFF6FF;
  border: 2px solid #3B82F6;
  transform: scale(1.05);
  box-shadow: 0 8px 24px rgba(59, 130, 246, 0.15);
  position: relative;
}
.pricing-card--recommended::before {
  content: "추천";
  position: absolute;
  top: -12px;
  left: 50%;
  transform: translateX(-50%);
  background: #3B82F6;
  color: #FFFFFF;
  padding: 4px 16px;
  border-radius: 9999px;
  font-size: 12px;
  font-weight: 600;
}
```

### 15.4 직렬 위치 효과 (Serial Position Effect)
목록의 첫 번째와 마지막 항목이 가장 잘 기억된다.

**적용:**
- 네비게이션: 가장 중요한 항목을 처음과 끝에 배치
- 모바일 탭바: 홈(첫번째), 프로필(마지막)
- 설문: 가장 중요한 질문을 처음에
- 기능 목록: 핵심 기능을 처음과 끝에

### 15.5 파킨슨의 법칙 (Parkinson's Law)
작업은 주어진 시간을 모두 소비한다.

**적용:**
- 폼 필드를 최소화 (불필요한 필드는 선택 사항으로)
- 자동 완성 적극 활용
- 진행률 표시로 완료 동기 부여
- 데드라인/카운트다운으로 긴급성 부여

### 15.6 테슬러의 법칙 (Tesler's Law / 복잡성 보존의 법칙)
모든 시스템에는 줄일 수 없는 최소 복잡성이 존재한다.

**적용:**
- 사용자가 아닌 시스템이 복잡성을 감당하게 한다
- 스마트 기본값으로 사용자 결정 최소화
- 복잡한 로직을 백엔드에서 처리, 프론트엔드는 단순하게
- 예: 주소 입력 → 우편번호 검색 API로 자동 완성

### 15.7 포스텔의 법칙 (Postel's Law / 견고성 원칙)
입력에는 관대하게, 출력에는 엄격하게.

**적용:**
- 전화번호 입력: 010-1234-5678, 01012345678, 010 1234 5678 모두 허용
- 검색: 오타 자동 교정, 유사어 매칭
- 날짜: 2024-01-01, 2024/01/01, 2024.01.01 모두 허용
- 출력은 항상 정규화된 형식으로 표시
