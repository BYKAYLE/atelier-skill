# Sisyphus Workflow Verification Reference

이 문서는 `sisyphus-workflow`가 완료를 선언하기 전에 확인해야 할 증거와 보고 규칙을 정리한다.

## 1. 기본 원칙

- 수정 자체는 완료가 아니다.
- 증거가 있어야 완료다.
- 관련 없는 기존 실패는 따로 분리해 설명한다.

## 2. Evidence Requirements

| 작업 유형 | 필요한 증거 |
|---|---|
| 파일 편집 | 변경 파일 diagnostics 또는 구조 검토 |
| 기능 변경 | 관련 테스트 또는 재현 절차 확인 |
| 빌드 영향 변경 | 빌드 성공 또는 적용 불필요 사유 |
| 위임 결과 사용 | 결과가 요구사항과 맞는지 검증 |
| 조사/리서치 | 근거 파일, 경로, 문서 출처 |

## 3. 완료 체크리스트

### 구현/수정
- todo가 모두 완료됨
- 변경 파일이 읽혀지고 내용이 확인됨
- diagnostics를 확인했거나, 해당 파일 타입에서 불가능한 이유를 설명함
- 관련 테스트를 실행했거나, 없는 이유를 설명함
- 필요 시 빌드를 실행했거나, 범위상 불필요함을 설명함
- 사용자 요청이 실제로 해결되었는지 한 번 더 대조함

### 조사/설명
- 근거가 되는 파일이나 문서를 실제로 읽음
- 추측이 아니라 읽은 내용 기준으로 답변함
- 추가 구현이 필요한 경우와 아닌 경우를 구분함

## 4. 실패 처리

- 내 변경으로 생긴 문제를 먼저 수정
- 관련 없는 선행 문제는 분리 보고
- 같은 방향으로 세 번 실패하면 더 밀어붙이지 말고 재평가

## 5. 최종 보고 체크리스트

최종 메시지에는 가능하면 아래가 있어야 한다.

1. 무엇을 바꿨는지 또는 무엇을 찾았는지
2. 어디서 바꿨는지
3. 왜 그 방향을 택했는지
4. 무엇을 검증했는지
5. 남은 가정, 제약, 선행 이슈

## 6. 금지 사항

- 검증 없는 완료 선언
- 테스트 실패를 숨기기
- 타입 에러 억지 무시
- 읽지 않은 코드 추측
