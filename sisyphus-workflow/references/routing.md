# Sisyphus Workflow Routing Reference

이 문서는 `sisyphus-workflow`가 어떤 상황에서 어떤 탐색/위임/스킬 선택을 해야 하는지 정리한 라우팅 기준표다.

## 1. Intent -> 기본 흐름

| Intent | 기본 행동 |
|---|---|
| research | 코드/문서 탐색 후 설명 |
| investigation | 근거 수집 후 findings 보고 |
| evaluation | 비교, 리스크, 추천안 제시 |
| fix | 재현 -> 원인 분석 -> 최소 수정 -> 검증 |
| implementation | 계획 -> 구현 -> 검증 |
| open-ended | 코드베이스 평가 -> 범위 설정 -> 실행 |

## 2. 자동 트리거

### 외부 레퍼런스 탐색 우선
- 사용자가 특정 라이브러리, 프레임워크, SDK, API를 언급함
- 공식 문서나 모범 사례가 필요함
- 익숙하지 않은 동작을 설명해야 함

### 내부 코드베이스 탐색 우선
- 2개 이상 모듈/레이어에 걸친 요청
- 흐름 추적이 필요함
- 기존 패턴을 먼저 찾아야 함

### 고수준 검토 고려
- 큰 설계 결정
- 큰 구현 완료 직후
- 두 번 이상 실패한 수정
- 보안/성능/아키텍처 우려 존재

## 3. 에이전트별 라우팅

### `explore`
사용 시점:
- 크로스레이어 흐름 파악
- 유사 구현 검색
- 디렉터리 구조가 익숙하지 않음

기대 산출물:
- 파일 경로
- 패턴 요약
- 어떤 파일을 기준으로 삼아야 하는지 추천

### `librarian`
사용 시점:
- 외부 패키지 언급
- 공식 문서 필요
- 오픈소스 구현 예시 필요

기대 산출물:
- 공식 문서 핵심 포인트
- 운영 환경 권장 패턴
- 참고할 예시 링크/요약

### `oracle`
사용 시점:
- 아키텍처 판단
- 어려운 디버깅
- 큰 작업 후 sanity review

기대 산출물:
- 방향성 검증
- 숨은 리스크
- 지금 접근을 유지할지 바꿀지에 대한 조언

### `metis`
사용 시점:
- 복잡한 요청
- 숨은 의도 분석 필요
- 요구사항 해석 실패 가능성 높음

기대 산출물:
- 숨은 요구사항
- 애매한 부분
- 실패 포인트와 안전한 기본값

### `momus`
사용 시점:
- 작업 계획 수립 직후
- 검증 기준이 중요한 작업

기대 산출물:
- 빠진 단계
- 검증 불충분한 지점
- 계획의 모호성

## 4. 로컬 스킬 기본값

| 작업 유형 | 우선 스킬 |
|---|---|
| UI/UX, 디자인 시스템, 접근성 | `ui-ux-pro-max` |
| 보안 리뷰, 인증/권한, 취약점 점검 | `security-router` |
| 큰 기능/서비스 단위 구현 | `autonomous-dev` |
| 스킬 개선/버전업 | `skill-evolve` |
| 과학/연구 도메인 | `k-dense-ai` |
| IT 현장 문제 | `it-field-support` |

## 5. 직접 처리해도 되는 경우

- 명백한 단일 파일 수정
- 단순 문자열 교체
- 이미 읽은 코드에 대한 짧은 설명
- 위임보다 직접 처리가 더 빠르고 안전한 trivial task
