# IT Field Support — 현장 IT 문제 해결 엔진

사용자는 "무슨 문제가 생겼는지"만 말한다. 진단과 해결은 이 스킬이 수행한다.

---

## 핵심 원칙

1. **진단 먼저, 조치 나중** — 증상만 보고 바로 조치하지 않는다. 반드시 진단 명령으로 원인을 특정한 뒤 조치한다
2. **비파괴 우선** — 포맷, 초기화 등 파괴적 조치는 최후 수단. 항상 비파괴적 해결을 먼저 시도한다
3. **단계적 에스컬레이션** — 간단한 조치 → 중간 조치 → 고급 조치 순서로 진행한다
4. **현재 상태 보존** — 조치 전 현재 설정을 백업/기록한다 (예: 레지스트리 export, IP 설정 메모)
5. **증거 기반 보고** — 명령어 실행 결과를 근거로 보고한다. 추측하지 않는다

## 워크플로우

### Phase 0: 상황 접수

사용자의 문제 설명을 받고 다음을 파악한다:

| 항목 | 확인 방법 |
|------|-----------|
| OS 종류 | 직접 질문 또는 접속 후 `systeminfo` / `sw_vers` 실행 |
| 접속 방식 | SSH 직접 접속 / 원격(PowerShell Remoting) / 현장 직접 조작 |
| 증상 | 사용자 설명 기반 |
| 문제 카테고리 | 아래 7개 중 분류 |

**카테고리 자동 분류:**

| # | 카테고리 | 키워드 |
|---|----------|--------|
| 1 | 오피스 라이센스/설치 | 오피스, 라이센스, 인증, 정품, 설치 안 됨, 365 |
| 2 | 네트워크 연결 | 인터넷, 네트워크, DNS, IP, 게이트웨이, 공유기, Wi-Fi |
| 3 | 공유폴더/NAS | NAS, 공유폴더, SMB, 네트워크 드라이브, 시놀로지, QNAP |
| 4 | 프린터 | 프린터, 인쇄, 출력, 스풀러 |
| 5 | 시스템 성능/서비스 | 느림, 멈춤, 블루스크린, 서비스, 부팅, CPU, 메모리 |
| 6 | AD/계정/권한 | 로그인, 비밀번호, 도메인, 그룹정책, 권한 |
| 7 | 디스크/저장 공간 | 용량 부족, 디스크, 포맷, 파티션 |

### Phase 1: 자동 진단

카테고리가 결정되면 해당 진단 명령어를 순서대로 실행한다.
OS에 따라 `references/windows-commands.md` 또는 `references/macos-commands.md`를 참조한다.

**진단 원칙:**
- 읽기 전용 명령어만 사용한다 (시스템 변경 없음)
- 결과를 분석하여 정상/비정상 항목을 분류한다
- 비정상 항목에서 근본 원인을 추론한다

---

### Phase 2: 원인 분석 및 해결 방안 제시

진단 결과를 바탕으로 사용자에게 보고한다:

```
🔍 진단 결과:
- [정상] 네트워크 연결: 게이트웨이 응답 정상
- [비정상] DNS 해석 실패: nslookup 타임아웃
- [비정상] DNS 서버 설정: 168.126.63.1 응답 없음

📋 원인: DNS 서버(168.126.63.1)가 응답하지 않음

🔧 해결 방안 (우선순위순):
1. DNS 서버를 8.8.8.8 / 8.8.4.4로 변경 (즉시 해결 가능)
2. 기존 DNS 서버 상태 확인 (관리자 확인 필요)

어떤 방법으로 진행할까요?
```

**중요:** 시스템 변경이 수반되는 조치는 반드시 사용자 승인 후 실행한다.

---

### Phase 3: 해결 실행

사용자 승인 후 조치를 실행한다.

**실행 원칙:**
- 조치 전 현재 설정 백업 (예: `netsh interface ip show config > backup.txt`)
- 한 번에 하나씩 변경하고 확인한다
- 변경 후 즉시 검증 명령어를 실행하여 해결 여부를 확인한다

---

### Phase 4: 검증 및 보고

조치 후 반드시 검증을 실행한다:

```
✅ 해결 완료:
- 문제: DNS 서버 미응답으로 인터넷 접속 불가
- 조치: DNS를 8.8.8.8 / 8.8.4.4로 변경
- 검증: nslookup google.com → 정상 응답 (142.250.207.14)
- 검증: ping google.com → 응답 시간 12ms
- 상태: 해결됨

⚠️ 참고:
- 이전 DNS: 168.126.63.1 (KT DNS, 현재 장애 또는 차단 상태)
- 원복 필요 시: netsh interface ip set dns "이더넷" static 168.126.63.1
```

## 카테고리별 상세 플로우

### 1. 오피스 라이센스/설치 문제

**진단 순서:**
1. 오피스 버전 및 설치 상태 확인
2. 라이센스 상태 확인 (LICENSED / GRACE / NOTIFICATION / OOB_GRACE)
3. 등록된 키 확인
4. 인증 서버 연결 확인

**해결 에스컬레이션:**
```
Level 1: 강제 재인증 시도 (/act)
Level 2: 기존 키 제거 → 정품 키 재입력 → 인증
Level 3: 인증 토큰 초기화 (tokens.dat 삭제) → 재인증
Level 4: 오피스 완전 제거 (SaRA / 수동) → 클린 재설치
Level 5: 시스템 파일 복구 (sfc /scannow, DISM) → 재설치
```

**포맷 전 필수 체크리스트:**
- [ ] sfc /scannow 실행했는가
- [ ] DISM /RestoreHealth 실행했는가
- [ ] 오피스 완전 제거 후 클린 설치 시도했는가
- [ ] 다른 사용자 계정에서 설치 시도했는가
- [ ] 안전 모드에서 설치 시도했는가

### 2. 네트워크 연결 문제

**진단 순서:**
1. NIC 상태 확인 (활성/비활성, 속도, 드라이버)
2. IP 설정 확인 (DHCP/고정, 서브넷, 게이트웨이)
3. 게이트웨이 응답 확인 (내부 네트워크)
4. 외부 연결 확인 (8.8.8.8)
5. DNS 해석 확인
6. IP 충돌 확인 (ARP 테이블)
7. 라우팅 테이블 확인

**해결 에스컬레이션:**
```
Level 1: IP 갱신 (ipconfig /release → /renew)
Level 2: DNS 캐시 플러시 → DNS 서버 변경
Level 3: NIC 비활성화 → 재활성화
Level 4: Winsock/TCP 스택 초기화
Level 5: 드라이버 재설치
```

### 3. 공유폴더/NAS 접속 문제

**진단 순서:**
1. 대상 호스트 ping 확인
2. SMB 포트(445) 연결 확인
3. SMB 클라이언트 설정 확인 (SMB1/2/3 버전)
4. 현재 네트워크 드라이브 연결 상태
5. 자격 증명 관리자 확인
6. 방화벽 규칙 확인

**해결 에스컬레이션:**
```
Level 1: 자격 증명 캐시 제거 → 재연결
Level 2: SMB 프로토콜 버전 맞춤 (NAS와 PC 간)
Level 3: 방화벽에서 SMB 허용
Level 4: 네트워크 검색 및 파일 공유 활성화
Level 5: 레지스트리에서 AllowInsecureGuestAuth 설정 (보안 고지 필수)
```

### 4. 프린터 문제

**진단 순서:**
1. 프린터 목록 및 상태 확인
2. 인쇄 스풀러 서비스 상태
3. 대기 중인 인쇄 작업 확인
4. 프린터 포트/IP 연결 상태
5. 드라이버 상태 확인

**해결 에스컬레이션:**
```
Level 1: 밀린 인쇄 작업 제거 → 스풀러 재시작
Level 2: 프린터 삭제 → 재추가
Level 3: 스풀러 완전 초기화 (PRINTERS 폴더 비우기)
Level 4: 드라이버 재설치
```

### 5. 시스템 성능/서비스 문제

**진단 순서:**
1. 시스템 기본 정보 (OS, 메모리, 부팅 시간)
2. CPU/메모리 상위 소비 프로세스
3. 디스크 사용량
4. 중지된 주요 서비스 확인
5. 최근 시스템 에러 로그 (이벤트 뷰어)
6. 시작 프로그램 목록

**해결 에스컬레이션:**
```
Level 1: 불필요한 프로세스/시작 프로그램 종료
Level 2: 임시 파일/캐시 정리
Level 3: 중지된 서비스 재시작
Level 4: sfc /scannow + DISM
Level 5: chkdsk (디스크 오류 시)
```

### 6. AD/계정/권한 문제

**진단 순서:**
1. 현재 로그인 사용자 및 그룹 확인
2. 도메인 참여 상태 확인
3. 도메인 컨트롤러 연결 확인
4. 보안 채널 상태 확인
5. 적용된 그룹 정책 확인
6. 계정 잠금 상태 확인

**해결 에스컬레이션:**
```
Level 1: 보안 채널 복구 (Test-ComputerSecureChannel -Repair)
Level 2: 그룹 정책 강제 갱신 (gpupdate /force)
Level 3: 도메인 재가입
Level 4: 로컬 관리자 계정으로 우회 접근
```

### 7. 디스크/저장 공간 문제

**진단 순서:**
1. 드라이브별 용량/사용량 확인
2. 대용량 폴더/파일 탐색
3. 디스크 건강 상태 확인
4. 휴지통/임시 파일 용량
5. Windows Update 캐시 용량

**해결 에스컬레이션:**
```
Level 1: 디스크 정리 (cleanmgr)
Level 2: Windows Update 캐시 삭제
Level 3: WinSxS 컴포넌트 정리
Level 4: 대용량 파일 사용자에게 안내 (삭제는 사용자 결정)
Level 5: chkdsk (디스크 건강 이상 시)
```

## 연결 방법 가이드

### SSH 접속 (Windows 10+)
```powershell
# 대상 PC에서 OpenSSH 서버 활성화
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
```

### PowerShell Remoting
```powershell
# 대상 PC에서 활성화
Enable-PSRemoting -Force

# 내 맥북에서 접속
Enter-PSSession -ComputerName 192.168.x.x -Credential (Get-Credential)
```

### 현장 직접 실행
Claude Code 또는 Antigravity를 현장 PC에서 직접 실행한다.
인터넷 연결 필수 (핫스팟 가능).
