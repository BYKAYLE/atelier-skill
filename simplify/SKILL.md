# Simplify: 파일 유형 인식 코드/문서 리뷰

변경된 파일을 리뷰하고, 발견된 문제를 수정한다.
**핵심 원칙: 코드는 최적화하고, 프롬프트는 보호한다.**

---

## Phase 1: 변경 파일 식별

`git diff` (staged 있으면 `git diff HEAD`)로 변경 파일 목록을 추출한다.
git 변경이 없으면 이번 대화에서 수정했거나 사용자가 언급한 파일을 대상으로 한다.

## Phase 2: 파일 유형 분류

**리뷰 전에 반드시 실행.** 각 파일을 아래 기준으로 분류한다.

### 분류 기준

| 유형 | 판별 조건 | 리뷰 모드 |
|------|----------|----------|
| **코드** | `.js`, `.ts`, `.py`, `.rs`, `.java`, `.go`, `.swift`, `.css`, `.html` 등 | **공격적 최적화** |
| **프롬프트/스킬** | 아래 조건 중 하나 이상 해당 | **보호 모드** |
| **일반 문서** | `.md`이지만 프롬프트 조건 미해당 | **가독성 중심** |

### 프롬프트/스킬 파일 판별 조건 (하나 이상 해당 시)

- 경로에 `skills/`, `references/`, `agents/` 포함
- 파일명이 `SKILL.md`, `AGENTS.md`, `CLAUDE.md`
- 파일 내용에 에이전트 지시 패턴 존재:
  - `당신은 ~전문가입니다` / `You are a ~expert`
  - `## 수행할 작업` / `## 검증 조건` / `## 출력 형식`
  - `## 권한 경계` / `## 합리화 방지`
  - YAML frontmatter에 `name:` + `description:` 존재

---

## Phase 3: 3개 리뷰 에이전트 병렬 실행

Agent tool로 3개 에이전트를 동시에 생성한다. 각 에이전트에게 **파일 유형 분류 결과**와 전체 diff를 전달한다.

### Agent 1: 코드 재사용 리뷰

변경된 각 파일에 대해:

1. **기존 유틸리티/헬퍼 검색** — 새로 작성된 코드를 대체할 수 있는 기존 함수가 있는지 Grep으로 탐색
2. **기존 기능과 중복되는 새 함수 플래그** — 대체할 기존 함수 제안
3. **기존 유틸리티로 대체 가능한 인라인 로직 플래그** — 수동 문자열 처리, 경로 조작, 환경 체크, 타입 가드 등

**[프롬프트/스킬 파일]**: 이 에이전트는 프롬프트 파일에서 "교차 참조 누락"만 확인한다:
- 같은 스킬 내 다른 파일에 이미 정의된 내용을 다시 작성한 경우 → 참조 링크 추가 제안 (삭제 아님)

### Agent 2: 코드 품질 리뷰

#### 코드 파일 기준 (공격적)
1. **불필요한 상태**: 기존 상태 중복, 파생 가능한 캐시, 직접 호출로 대체 가능한 옵저버
2. **파라미터 비대화**: 구조 개선 대신 새 파라미터를 추가한 경우
3. **약간의 차이만 있는 복사-붙여넣기**: 공유 추상화로 통합해야 할 근-중복 코드
4. **추상화 누수**: 내부 상세 노출, 기존 추상화 경계 위반
5. **문자열 기반 코드**: 상수/enum/타입이 있는데 원시 문자열 사용

#### 프롬프트/스킬 파일 기준 (보호)
1. **용어 불일치**: 같은 개념에 다른 이름 사용 (예: "Mode A" vs "서비스 빌더")
2. **파일 간 정합성**: 한 파일에서 변경된 Phase 이름/흐름이 다른 파일에 반영되지 않음
3. **죽은 참조**: 삭제된 섹션/파일을 여전히 참조하는 링크

**프롬프트 파일에서 플래그하지 않는 것:**
- 서비스 빌더/피처 빌더처럼 의도적으로 분리된 유사 섹션
- 체크리스트, Step, 구체적 예시 나열 (이것은 기능적 콘텐츠)
- 에이전트 프롬프트 템플릿 내부의 반복적 구조 (각 템플릿은 독립적)

### Agent 3: 효율성 리뷰

#### 코드 파일 기준 (공격적)
1. **불필요한 작업**: 중복 계산, 반복 파일 읽기, 중복 API 호출, N+1 패턴
2. **병렬화 누락**: 독립 작업의 순차 실행
3. **핫패스 비대화**: 시작/요청/렌더 경로에 추가된 블로킹 작업
4. **불필요한 존재 확인**: 작업 전 파일/리소스 존재 사전 체크 (TOCTOU)
5. **메모리**: 무한 성장 자료구조, 정리 누락, 이벤트 리스너 누수
6. **과도한 범위**: 일부만 필요한데 전체 파일 읽기, 하나 필터링인데 전체 로드

#### 프롬프트/스킬 파일 기준 (보호)
1. **토큰 효율**: 컨텍스트 로드 시 불필요하게 큰 섹션 (단, 내용 손실 없이 압축 가능한 경우만)
2. **참조 구조 개선**: 인라인 반복 대신 `상세: {파일} 참조`로 대체 가능한 경우 (원본 보존 전제)

**프롬프트 파일에서 플래그하지 않는 것:**
- 상세한 나열 (분위기/톤, 색감, 참고 서비스 등) → 에이전트 행동 품질의 핵심
- 각 Phase/Step의 구체적 절차 → 에이전트가 "뭘 해야 할지" 아는 근거
- 테이블, 체크리스트, 번호 매긴 항목 → 기능적 콘텐츠

---

## Phase 4: 영향 평가 + 수정

3개 에이전트의 결과를 수집한 후, **수정 전에 영향을 평가**한다.

### 코드 파일
발견 항목을 직접 수정한다. false positive면 건너뛴다.

### 프롬프트/스킬 파일
각 발견 항목에 대해 아래 게이트를 통과해야 수정한다:

```
1. 이 수정으로 삭제/압축되는 내용이 있는가?
   → 없음 (용어 교체, 참조 링크 추가 등): 수정 진행
   → 있음: 2번으로

2. 삭제되는 내용이 아래 보호 대상에 해당하는가?
   - 번호 매긴 Step/단계 (1, 2, 3...)
   - 체크리스트 항목 (- [ ])
   - 구체적 예시 나열 (분위기/톤, 색감 등)
   - 에이전트 프롬프트 템플릿 내부 지시문
   - 테이블 행
   - Phase 흐름 설명
   → 해당: 수정 금지 (보고만)
   → 미해당: 3번으로

3. 삭제 후에도 에이전트가 동일한 행동을 할 수 있는가?
   → 예 (순수 중복, 완전히 동일한 문장의 반복): 수정 진행
   → 아니오/불확실: 수정 금지 (보고만)
```

### 보고 형식

수정 완료 후 요약:

```
## 수정 완료
- [파일:라인] 설명 (유형: 코드/프롬프트)

## 보류 (프롬프트 보호)
- [파일:라인] 발견 내용 — 보류 사유: {보호 대상 해당/영향 불확실}

## 코드 클린 확인
- {이상 없는 파일 목록}
```
